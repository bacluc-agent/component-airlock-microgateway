= Parameters

The parent key for all of the following parameters is `airlock_microgateway`.

Api reference for Gateway API can be found here: https://gateway-api.sigs.k8s.io/reference/spec

Api reference for Airlock Microgateway CRs can be found here: https://docs.airlock.com/

== Derived names and cross-references

Resource names default to the (hyphenated) instance name, and the following cross-references are derived automatically. They can still be overridden per instance.

This follows the same multi-instance pattern as https://github.com/projectsyn/component-argocd[component-argocd]: each instance key becomes the namespace and the (hyphenated) name of the resources created for that instance.

* `gateway.spec.infrastructure.parametersRef.name` — the GatewayParameters name
* `gatewayParameters.spec.defaults.sessionHandlingRef.name` — the SessionHandling name (or the `sessionHandling.metadata.name` override)
* `sessionHandling.spec.persistence.redisProviderRef.name` — the RedisProvider name (or the `redisProvider.metadata.name` override)
* `httpRedirect.spec.parentRefs[].name` — the Gateway name
* `pdb.metadata.name`/`namespace`/`labels` — the instance name
* `egressNetpol.spec.podSelector.matchLabels['gateway.networking.k8s.io/gateway-name']` — the Gateway name

== `namespace`

[horizontal]
type:: string
default:: `syn-airlock-microgateway`

The namespace in which to deploy this component.

== Example

[source,yaml]
----
namespace: example-namespace
----

== `gatewayparameters.spec.features.externalNameServicesAllowed`

[horizontal]
type:: boolean
default:: `false`

Note that this is only available from v5.0.0 see https://github.com/airlock/microgateway/releases/tag/5.0.0 and configurable since v4.8.6.

== Example

To set it on a specific instance.
[source,yaml]
----
instances:
  vshn-default-test-01:
    gatewayParameters:
      spec:
        features:
		  externalNameServicesAllowed: true
----

To set it on all instanes of an environment.
[source,yaml]
----
default:
  gatewayParameters:
    spec:
      features:
        externalNameServicesAllowed: true
----

== `customResponses`

Custom responses are configured as a single entry per response code under `customResponses` (either on `default` or per instance).
If an entry contains a status-code `matcher`, the component automatically generates the `CustomResponse` resource and the corresponding entries in `gatewayParameters.spec.defaults.customResponses.local` and `.upstream` for every instance.
There, `range` is emitted with `from`/`to` for local and with `start`/`end` for upstream references automatically. See
https://docs.airlock.com/microgateway/5.0/index/api/crds/gateway-parameters/v1alpha1/index.html#gatewayparametersspecdefaultscustomresponses[Airlock Microgateway docs].

The matcher is optional: an entry without `matcher` only creates the `CustomResponse` with the entry value used as its spec verbatim, and generates no references. This keeps hand-written `gatewayParameters.spec.defaults.customResponses` lists working as before.

The first matching entry is used.
The response name keys are ordered lexicographically, so name ranges so all entries sort in the desired matching order.

For placeHolders see https://www.envoyproxy.io/docs/envoy/latest/configuration/advanced/substitution_formatter#config-advanced-substitution-operators[envoy substitution operators].

== Example

[source,yaml]
----
default:
  customResponses:
    "401":
      matcher:
        exact: 401
      customResponses:
        text/html:
          body:
            value: |
              <!DOCTYPE html>
              <html lang="de">
              <head>
                  <meta charset="utf-8">
                  <meta name="viewport" content="width=device-width, initial-scale=1.0">
                  <title>Customer Error 401</title>
              </head>
              <body>
              <main>
                  <h1><span class="textcode">Error </span>401</h1>
                  <p lang="de">You can't access this application.</p>
              </main>
              </body>
              </html>
          headers: {}
----
