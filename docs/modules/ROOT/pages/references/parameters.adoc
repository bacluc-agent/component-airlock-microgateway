= Parameters

The parent key for all of the following parameters is `airlock_microgateway`.

Api reference for Gateway API can be found here: https://gateway-api.sigs.k8s.io/reference/spec

Api reference for Airlock Microgateway CRs can be found here: https://docs.airlock.com/

== `namespace`

[horizontal]
type:: string
default:: `syn-airlock-microgateway`

The namespace in which to deploy this component.

== Example

[source,yaml]
----
namespace: example-namespace
----

== `gatewayparameters.spec.features.externalNameServicesAllowed`

[horizontal]
type:: boolean
default:: `false`

Note that this is only available from v5.0.0 see https://github.com/airlock/microgateway/releases/tag/5.0.0 and configurable since v4.8.6.

== Example

To set it on a specific instance.
[source,yaml]
----
instances:
  vshn-default-test-01:
    gatewayParameters:
      spec:
        features:
		  externalNameServicesAllowed: true
----

To set it on all instanes of an environment.
[source,yaml]
----
default:
  gatewayParameters:
    spec:
      features:
        externalNameServicesAllowed: true
----

== `default.gatewayParameters.spec.defaults.customResponses`

Allows to set the local and upstream customResponses, see
https://docs.airlock.com/microgateway/5.0/index/api/crds/gateway-parameters/v1alpha1/index.html#gatewayparametersspecdefaultscustomresponses[Airlock Microgateway docs].

The first matching entry wins, so list exact status codes before catch-all ranges.

`instances.<instance>.gatewayParameters` is merged onto the defaults with a jsonnet `mergePatch`.
A `mergePatch` *replaces* arrays instead of appending to them, so an instance override of `...customResponses.local` or `...customResponses.upstream` must repeat the complete desired array, including all default entries which should be kept.
To extend the default list instead, compose it from multiple reclass classes: reclass appends the list entries contributed by different classes.

For placeHolders see https://www.envoyproxy.io/docs/envoy/latest/configuration/advanced/substitution_formatter#config-advanced-substitution-operators[envoy substitution operators].

== `default.customResponses`

Maps a name to the `spec` of a `CustomResponse` object, see the
https://docs.airlock.com/microgateway/5.0/index/api/crds/custom-response/v1alpha1/index.html[Airlock Microgateway CustomResponse docs].
Each key creates a `microgateway.airlock.com/v1alpha1` `CustomResponse` with that name.

[source,yaml]
----
default:
  customResponses:
    "401":
      content:
        - contentType: text/html
          body:
            value: |
              <h1>Access Denied</h1>
----

The response body is either inlined in `spec.content[].body.value` or loaded from a `ConfigMap` via `spec.content[].body.valueFrom.configMapKeyRef`.

The `customResponseRef.name` used in `gatewayParameters.spec.defaults.customResponses.{local,upstream}` must match one of these keys.

`instances.<instance>.customResponses` is merged onto `default.customResponses` per key with `mergePatch`, so an instance can override or add individual responses without repeating the others.

== Example

[source,yaml]
----
default:
  gatewayParameters:
    spec:
      defaults:
        customResponses:
          local:
            - statusCodeCondition:
                matcher:
                  exact: 401
              customResponseRef:
                name: "401"
            - statusCodeCondition:
                matcher:
                  range:
                    start: 400
                    end: 499
              customResponseRef:
                name: "4xx"
  customResponses:
    "401":
      content:
        - contentType: text/html
          body:
            value: |
              <!DOCTYPE html>
              <html lang="de">
              <head>
                  <meta charset="utf-8">
                  <meta name="viewport" content="width=device-width, initial-scale=1.0">
                  <title>Customer Error 401</title>
                  <style>
                      @media (max-height: 550px) {
                          body { overflow-y: auto; height: auto; }
                      }
                  </style>
              </head>
              <body>
              <main>
                  <h1><span class="textcode">Error </span>401</h1>
                  <section>
                    <h2 lang="de">Access Denied</h2>
                    <p lang="de">You can't access this application.<br>
                    Additional info: <a href="https://support.customer.com">Support</a>.</p>
                  </section>
              </main>
              <footer>
                  REQUEST ID: %STREAM_ID%
              </footer>
              </body>
              </html>
          headers: {}
    "4xx":
      content:
        - contentType: text/html
          body:
            value: |
              %RESPONSE_CODE%
----

== Class-based setup

Define the response bodies and the gateway parameter refs in reclass classes and include them from the instance class.

bodies.yml
[source,yaml]
----
parameters:
  airlock_microgateway:
    default:
      customResponses:
        "4xx":
          content:
            - contentType: text/html
              body:
                value: |
                  %RESPONSE_CODE%
----

refs.yml
[source,yaml]
----
parameters:
  airlock_microgateway:
    default:
      gatewayParameters:
        spec:
          defaults:
            customResponses:
              local:
                - statusCodeCondition:
                    matcher:
                      range:
                        start: 400
                        end: 499
                  customResponseRef:
                    name: "4xx"
----

instance.yml
[source,yaml]
----
classes:
  - bodies
  - refs

parameters:
  airlock_microgateway:
    instances:
      example-instance: {}
----

Each class file has to be passed to the compilation so that its name is available as a class, for example:

[source,bash]
----
commodore component compile . --search-paths . -f bodies.yml -f refs.yml -f instance.yml
----
